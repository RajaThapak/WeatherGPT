# WeatherGPT — Low-Latency Architecture (v2)
## Synthesis of PRD v1.3 (Section 7) + Session Decisions

**Status:** Draft, reflects decisions made after PRD v1.3 — supersedes Section 7's diagram and the FE-6/BE-5 rows in Section 6/8/11 of `WeatherGPT_PRD.md`. Treat this as the current source of truth for architecture; fold back into a v1.4 PRD once confirmed.

**Decisions this version bakes in:**
- Database stays **PostgreSQL** (PostGIS + TimescaleDB) — MongoDB considered and rejected; this domain (district-polygon geo-matching, time-series climate rollups) is PostGIS/Timescale's exact use case.
- **RAG layer (BE-5) cut from MVP.** All factual/numeric answers already route through the structured Weather Data service, not the LLM — that already covers hallucination risk for the queries that matter. `pgvector` is not provisioned in MVP.
- **Globe replaces the flat map panel**: Cobe (decorative/idle) + MapLibre GL JS globe projection (functional search → fly-to → pin), replacing the PRD's original Leaflet plan for FE-6.
- **Voice is two-provider**: Whisper (STT, free/self-hosted) stays; **Rime (TTS, paid)** replaces Coqui/eSpeak-NG for voice *output* only. Rime is the one non-free-forever component in the stack and is rate-limited accordingly.
- **Chat is the single entry point** for both the weather Q&A and the globe fly-to — typing/speaking a location in chat drives the globe, not a separate search box.

## 2. What changed vs. PRD v1.3 Section 7, and why

| Component | PRD v1.3 | This version | Why |
|---|---|---|---|
| Map/location UI | Leaflet + OSM (FE-6) | Cobe (idle) + MapLibre GL JS globe projection | Recreates the requested globe/fly-to UX; MapLibre is a near-drop-in for Leaflet's API, ~230KB, degrades to flat 2D on low-end devices — doesn't blow the TTI budget the way full CesiumJS would |
| Climate Q&A grounding | RAG layer (BE-5), pgvector/HNSW | Cut from MVP | Every query type that actually needs to be *correct* (current weather, forecast, trends, alerts) already bypasses the LLM entirely via the structured Weather Data service. RAG would only serve open-ended explanatory questions — narrow slice, not worth the ingestion/indexing pipeline for a 12-week MVP |
| Voice output | Coqui TTS / eSpeak-NG (free, self-hosted) | Rime (paid API) | Explicit user choice for voice quality/latency. Only exception to the zero-cost pillar — scoped narrowly to TTS output, rate-limited per user so it can't blow the pilot budget |
| Voice input | Whisper | Unchanged — Whisper | No reason to pay for STT when Whisper self-hosted is already free and streaming-capable |
| Chat ↔ location flow | Search box (implicit, separate from chat) | Chat is the single entry point; typing/speaking a place name drives the globe fly-to directly | Matches the requested UX — no separate search UI competing with chat |
| Database | PostgreSQL + PostGIS + TimescaleDB + pgvector | Same, minus pgvector for now | MongoDB considered and rejected (see below); pgvector deferred since RAG is cut |

**Why Postgres over MongoDB (recap of the decision):** this domain is geospatial-heavy (district-polygon matching for alerts) and time-series-heavy (climate rollups). PostGIS is the most precise free option for the former; TimescaleDB's continuous aggregates automate the latter. MongoDB's 2dsphere index and time-series collections can approximate both but with less precision and more manual rollup logic — a worse fit for exactly the two hardest parts of this app.

## 3. Latency techniques added by the new pieces

| New/changed piece | Latency technique |
|---|---|
| Chat-driven globe fly-to | Location resolution + weather fetch happen server-side in parallel and return together — client gets `{lat, lon, zoom}` + weather payload in one round trip, not a fly-to call followed by a separate weather call |
| MapLibre globe | Lazy-loaded on first search/chat use, not on initial page paint — Cobe (5KB) covers the idle "wow" moment for free |
| Voice STT | Streamed partial transcripts (Whisper), not wait-for-silence-then-transcribe |
| Voice TTS | Rime streamed audio chunks played as they arrive, not wait-for-full-synthesis — mirrors the existing "stream, don't wait" principle for chat tokens |
| Rime cost/latency guard | Per-user/session rate limit at the API gateway — protects both budget and prevents one heavy voice user from queuing behind others on a paid rate limit |

## 4. Carried-over open items (unresolved, flagged in earlier PRD review — not solved by this version)

- **Alert fallback gap**: Web Push doesn't reach users without an installed, subscribed PWA — exactly the low-connectivity personas (farmer, fisherman) this product targets most. No SMS/USSD fallback is in MVP scope. Worth a decision before Phase 3 (alerts) starts.
- **Single LLM provider risk**: Groq/Gemini fallback wiring is still an assumption, not a built task in the 8.1 breakdown.
- **India-region hosting**: still unconfirmed (MeghRaj vs. Render/Railway/Fly.io Asia regions) — affects both latency and potential data-residency requirements for a government client.
